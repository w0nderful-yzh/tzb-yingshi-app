# 系统设计与开发文档——守护安（SafeGuard）Android 家属端应用架构

- 赛题编号：XH-202617
- 对应方向：诈骗识别及预警（防诈）
- 应用名称：守护安（SafeGuard）
- 应用定位：面向家属的风险预测与提前介入应用

---

## 一、概述

守护安是一款面向居家养老场景的家属端 Android 应用，承载诈骗风险识别系统的"最后一公里"：将后端对老人通话与居家场景的多模态分析结果，以趋势预测、分级预警与处置闭环的形式呈现给家属，并承担实时直播复核、持续音视频监测与风险通知等关键职责。

应用的总体设计遵循三个原则。其一，**风险预测优先**：产品不是"事故发生后发一条消息"，而是在风险尚未发展成损失前，根据连续证据呈现风险趋势并推动家属介入，首页直接展示当前风险状态与今日预测。其二，**无感监测**：监测过程完全基于摄像头音视频，老人无需佩戴设备或操作界面，页面关闭、锁屏甚至切到桌面后，持续守护服务仍保持运行。其三，**诚实占位**：当前仅落地防诈方向的完整能力，跌倒与心理关怀按统一事件边界保留接入位，不展示模拟结果，避免与真实效果不符。

应用采用 Kotlin + Jetpack Compose（Material 3）实现，遵循 MVVM 架构与单向数据流，网络层基于 Retrofit + OkHttp + kotlinx.serialization，实时通知基于一次性票据 WebSocket，萤石设备能力基于萤石官方 EZOpenSDK 原生接入。为保证演示阶段可控与低成本联调，依赖注入采用轻量手写 ServiceLocator 而非重量级框架，待功能稳定后可持续演进。

## 二、总体架构

### 2.1 分层模型

应用按职责划分为三层，遵循单向依赖原则：UI 层只依赖数据层暴露的仓库接口与数据模型，数据层不感知任何界面细节，各层之间通过明确的契约（数据类与接口）衔接，保证层与层之间可以独立修改与测试。

最外层是**入口层**，由 Application、主 Activity 与导航组件构成，负责应用装配、登录态管理与页面路由；中间是**数据层**，覆盖网络通信、本地登录态、实时推送、媒体采集与统一仓库，是界面层唯一的取数来源；最内是**界面层**，由页面、视图模型与通用组件构成，负责把数据状态渲染为可交互的界面。持续守护前台服务在逻辑上归属于数据层的媒体与实时通道，但因其生命周期独立于界面，设计中将其作为与界面层并行的常驻能力单独管理。

```text
┌────────────────────────────────────────────────┐
│ 入口层：Application / MainActivity / 导航        │
├────────────────────────────────────────────────┤
│ 界面层：Screen(Compose) ── ViewModel ── UiState │
│         通用组件 / 主题 / 状态容器               │
├────────────────────────────────────────────────┤
│ 数据层：Repository（唯一数据入口）               │
│    ├ 网络：Retrofit + OkHttp + 拦截器            │
│    ├ 本地：AuthStore（Token 持久化）             │
│    ├ 实时：AlertWebSocketClient（票据订阅）      │
│    └ 媒体：EZOpenSDK + 音频转发 + 前台服务       │
├────────────────────────────────────────────────┤
│ 服务端：FastAPI 后端 · PostgreSQL · 萤石开放平台 │
└────────────────────────────────────────────────┘
```

### 2.2 技术选型

| 领域 | 选型 | 说明 |
|---|---|---|
| 语言与 UI | Kotlin + Jetpack Compose（Material 3） | 声明式 UI，统一状态驱动渲染 |
| 架构模式 | MVVM + StateFlow + 单向数据流 | ViewModel 持有状态，界面只消费 |
| 依赖注入 | 手写 ServiceLocator | Demo 阶段降低接入成本，接口可替换 |
| 网络 | Retrofit 2 + OkHttp + kotlinx.serialization | 契约与接口文档一一对应 |
| 实时通知 | OkHttp WebSocket + 一次性票据 | 免鉴权握手，断线指数退避重连 |
| 萤石能力 | EZOpenSDK 5.30.2 | 原生 H.264/H.265 直播与 PCM 音频回调 |
| 导航 | Navigation Compose | 路由集中定义，深链直达事件详情 |

## 三、入口层设计

入口层负责把外部事件（启动、通知点击、登录状态变化）转化为界面行为。Application 在进程启动时完成依赖装配，将认证存储、网络客户端与统一仓库三个核心对象注册进 ServiceLocator；登录态以流的形式暴露，主 Activity 收集该流后决定渲染登录页还是主界面，实现登录/退出时整棵界面树的自动切换。

导航采用集中式路由定义，所有页面路径统一收敛在路由对象中，杜绝硬编码散落。导航图覆盖首页、现场复核、消息、预警详情、个人中心等页面，其中预警详情接收事件标识作为导航参数。特别地，风险通知点击会产生深链跳转：主 Activity 通过新增意图读取待打开的事件标识，通过一次性的导航事件跳转到对应预警详情，并保证导航完成后消费该事件，避免重复跳转。

## 四、数据层设计

数据层是应用稳定性的根基，设计上强调"界面只面对一个仓库、仓库统一消化三类失败"的原则：后端统一响应包装、HTTP 错误与网络异常被统一转换为标准结果类型，界面层无需感知底层细节。

### 4.1 数据模型与契约驱动

数据模型严格对齐接口契约文档，字段命名与后端约定的下划线风格保持一致，并通过序列化注解与后端 JSON 一一对应。模型对未知字段采取忽略策略，后端新增字段不会导致客户端崩溃，保证前后端可以错版本演进；空值字段自动收敛为默认值，减少空指针风险。风险事件模型内嵌防诈专属字段（诈骗场景、S0-S5 状态、状态索引、处置建议、两级校验状态），使列表与详情页可以直接渲染趋势摘要，无需为首页再次请求详情。

### 4.2 网络层

网络层由接口定义与装配模块两部分组成。接口定义以 Retrofit 注解声明全部服务端接口，路径与接口文档逐条对应；装配模块负责创建共享的 HTTP 客户端，并挂载三个关键拦截器：认证拦截器自动为请求附加登录令牌，非查询请求自动附加幂等键，保证重复提交不产生重复业务；鉴权失效拦截器在收到未授权响应时自动清除本地登录态并回落登录页；开发期日志拦截器提供基础请求观测。应用内置契约级 Mock 拦截器，可整体切换到本地演示数据，用于离线演示与前端先行联调。

### 4.3 仓库层

统一仓库是界面层唯一的取数入口，封装了认证、事件、设备、家属、媒体等全部业务访问。仓库内部将后端响应、HTTP 异常与网络故障统一转换为标准结果类型，并根据业务语义给出可读的中文提示。登录流程中，仓库还承担了角色校验职责：仅允许家属账号进入，非家属账号登录后立即清除会话，从源头保证应用面向的单一角色边界。

### 4.4 本地认证存储

登录令牌以安全的方式保存在应用私有存储中，并通过状态流对外暴露，使认证状态的变化能够即时驱动界面切换。网络层在请求时自动携带令牌，令牌失效时由拦截器统一触发清理，形成"失效即退出"的闭环。

### 4.5 实时通知通道

实时通知采用"一次性票据 + WebSocket"的安全握手方案：应用先从服务端申请一个有效期 60 秒的临时票据，再携带该票据建立风险事件订阅连接，服务端校验通过后按事件推送。票据短期有效且用后即弃，客户端不保存长期密钥，兼顾了实时性与安全性。连接断开时，客户端自动重新申请票据并以 1 至 30 秒的指数退避策略重连，保证长期驻留场景下的可靠性。推送到达后立即转换为高优先级系统通知，点击通知可直接深链进入对应事件详情。

### 4.6 媒体采集与持续守护

媒体能力是本应用区别于一般消息类应用的独特部分，包含两条并行链路。

**可视预览链路**：通过后端签发的临时会话（应用密钥与令牌均只在服务端签发，App 密钥不下发客户端）初始化萤石原生 SDK，播放设备的原始 H.264/H.265 码流，供家属在首页与现场复核页远程查看实时画面。

**持续守护链路**：由前台服务承载，即使页面关闭、锁屏或切换应用仍持续运行。守护服务在后台静音解码摄像头音轨，通过 SDK 的音频回调获取 16kHz 单声道 PCM 数据，按 1 秒批次有界、非阻塞地转发给后端。音频转发采用有界通道并设置背压策略：当网络拥塞时优先丢弃最旧的数据块，保证告警延迟不会无限累积，而语音切分的语义边界完全由后端语音活动检测负责，客户端只做传输层的批量转发，职责边界清晰。守护服务同时维护媒体链路与告警链路两条连接，各自独立重连互不影响，并通过前台通知常驻展示守护状态，用户可一键停止。

守护服务的生命周期通过偏好设置持久化：进程被杀后系统按粘性策略重建，重建后自动恢复守护；登录态清除时守护自动停止，避免无凭证的空转连接。

## 五、界面层设计

界面层采用声明式 UI 与 MVVM 模式，遵循"界面只消费状态、不直接发起业务"的单一方向。

### 5.1 状态管理

每个页面由对应的视图模型持有页面状态，状态通过状态流暴露给界面。页面状态统一采用加载、成功、失败三态建模，配以统一的状态容器组件：加载时显示进度指示，失败时展示错误信息与重试按钮，成功时渲染内容，空数据由各页面自行呈现空态占位。操作类动作（如处置事件）单独维护执行状态，区分空闲、执行中、完成与失败，防止重复提交并给出操作反馈。

### 5.2 通用组件与主题

界面层沉淀了一套可复用的通用组件，包括状态容器、事件卡片、大按钮、级别徽标、底部导航与页面头等。事件卡片以左侧级别色条、图标、标题、摘要与状态标签构成，并对防诈事件做场景化渲染（区分电诈风险与入户风险）；告警级别徽标采用颜色、图标、文字三通道表达，不单独依赖颜色，兼顾色觉障碍用户的可用性。主题基于 Material 3 建立，以白色底、克制配色与清晰触控热区体现家属端适老化的视觉基调。

### 5.3 页面构成

应用以首页、消息、我的三个一级导航组织功能。首页展示被守护老人信息、内嵌真实直播、今日风险概览与快捷入口，风险概览直接复用事件模型中的防诈状态摘要，做到首页零额外请求；消息页按风险事件流展示预警卡片，每条预警携带对应时间戳画面；预警详情页按固定顺序呈现事件主画面、预测原因与风险阶段、关联画面、介入建议与处置操作，家属可一键开始介入、现场直播复核、解除风险或标记误报，全部动作通过状态更新回写后端并留痕审计。现场复核页独立承担直播能力，作为介入动作的配套场景。个人中心承载账号信息、设备清单、联系人及持续守护的开关键。

## 六、与后端及萤石平台的集成设计

应用与后端通过 REST 接口与 WebSocket 两条通道协作，接口路径与契约文档逐条对应，字段命名由后端契约决定，客户端严格遵循。

安全边界上遵循"密钥永不下发"原则：萤石应用密钥、设备秘钥等敏感凭证一律由后端保管与签发，客户端仅获得短期有效的直播会话令牌与访问令牌，令牌过期后自动重新申请。音频上传接口以二进制流上传解码后的 PCM 数据，并携带采样率头信息，后端据此完成语音活动检测与转写，客户端不参与语义分析，只做可靠传输。

萤石能力的接入封装在独立的运行时管理对象中：进程内仅初始化一次 SDK，按需切换应用密钥与访问令牌，并统一关闭 SDK 日志，避免令牌泄漏进日志。该运行时同时服务于持续守护服务与可视预览链路，保证单进程内 SDK 生命周期一致。

## 七、安全与合规设计

应用在安全与合规方面做了系统性设计。凭证安全上，平台密钥不下发客户端，访问令牌短期有效并随失效自动清理，日志默认关闭 SDK 输出；数据传输上，全部业务走后端统一接口，客户端不直连算法、不直连数据库；隐私保护上，App 不保存通话原始数据，音频仅作为实时监测流转发、不持久化，联系人电话等敏感字段由服务端脱敏后下发；合规边界上，应用明确不执行自动转账拦截、不自动报警，定位为辅助监测与人工决策支持工具，并在界面与后端双重约束下保证"未接入的平台能力不伪装已实现"。

## 八、构建与部署

应用工程采用 Gradle 管理，构建参数支持按环境覆盖服务端地址，默认配合本地模拟器端口转发，真机可通过构建参数指定局域网地址，无需改代码。Mock 开关可在离线场景下整体切换为本地契约演示数据。工程同时兼容萤石 SDK 所需的处理器架构，产出的安装包可直接安装部署。应用侧不含任何密钥，服务端按容器化编排一键启动，形成"后端可一键拉起、App 可一键联调"的完整可运行交付。

## 九、后续演进

应用当前的架构为后续能力演进预留了明确空间：认证体系将进一步补充注册、改密与令牌刷新，并将令牌存储升级为系统级加密保护；实时通知将在 WebSocket 之外补充厂商推送通道，提升离线必达能力；入户诈骗场景将对接萤石正式访客与停留事件字段，补足跨时间证据；历史回放与设备语音提醒的后端能力就绪后将即时接通。跌倒与心理健康两个方向将复用统一事件中心与既有页面骨架接入，与防诈能力共同构成面向老年人居家安全的综合防护应用。
