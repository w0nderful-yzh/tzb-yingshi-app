# 家属端风险预测与提前介入产品说明

> 当前 App 只面向家属。正式落地防诈预测与介入闭环；跌倒风险预测、心理健康趋势仅保留模块占位，不展示模拟结论。

## 1. 产品定位

产品不是“事故发生后发一条消息”，而是在风险尚未发展成损失前，根据连续证据判断趋势并推动家属介入：

```text
设备证据 → 时间窗融合 → S0-S5 趋势预测 → 家属提前介入 → 现场复核 → 结果审计
```

当前防诈覆盖电信诈骗和入户诈骗，但首页不拆分两类入口。家属首先需要知道“风险正在发展到哪一步、现在该做什么”；具体场景只在预警消息和详情中呈现。

明确不做：

- 不把单个关键词、人数或通话状态直接判为诈骗；
- 不等到已经转账或已经造成损失才生成事件；
- 不宣称 App 能冻结交易、自动报警或代替家属处置；
- 不在当前版本生成跌倒结果、情绪评分、健康趋势或陪聊内容。

## 2. 已实现闭环

### 2.1 预测

防诈状态机对跨模态、跨时间证据进行组合判断：

| 阶段 | 风险含义 | 家属端呈现 |
|---|---|---|
| S0 | 未出现有效风险链 | 持续监测，不打扰 |
| S1 | 出现弱可疑迹象 | 留存观察，不制造高危告警 |
| S2 | 可疑身份接触 | 提示家属关注并核实身份 |
| S3 | 敏感信息试探 | 生成待介入预警 |
| S4 | 转账、验证码或远程授权诱导 | 建议立即介入 |
| S5 | 保密控制与执行行为组合 | 高风险介入，优先现场核实 |

事件列表直接返回预测摘要，避免首页为每条事件再次请求详情：

```json
{
  "type": "fraud_suspected",
  "fraud_state": "S4_ACTION_INDUCEMENT",
  "fraud_state_index": 4,
  "fraud_state_label": "敏感操作诱导",
  "fraud_decision": "block"
}
```

### 2.2 介入

当前版本的真实介入能力包括：

1. 家属点击“开始介入”，事件从 `open` 进入 `acknowledged`；
2. 家属查看预测依据和实时画面，主动联系或现场核实；
3. 风险解除后标记 `resolved`，误判标记 `false_alarm`；
4. 所有状态变化写入事件动作审计，避免只有一条不可追踪的通知。

摄像头自动语音提醒、电话外呼和系统通知推送必须接入真实平台能力后再展示。当前不得用本地按钮或固定文案冒充这些动作已经执行。

## 3. 场景证据

### 电信诈骗

```text
phone_call_active
  + identity_claim / emergency_pretext / benefit_lure
  + credential_request / sensitive_info_request
  + money_instruction / remote_control_instruction
  + secrecy_control
```

### 入户诈骗

```text
visitor_presence / people_count_context
  + benefit_lure / identity_claim
  + amount_request / money_instruction
  + urgency_pressure / secrecy_control
```

单帧人数和单次通话只作为场景事实。入户诈骗要依赖连续访客轨迹或停留事件；正式萤石字段未到位前，应标记为基础证据接入，不能夸大能力。

## 4. 家属端信息架构

一级导航固定为：

1. `首页`：被守护家人、首页内嵌真实直播、查看直播/历史回看/介入提醒/更多设置四个快捷入口，以及今日预测；
2. `消息`：以消息卡形式呈现预测、介入和已结束的系统记录，每条诈骗预警必须携带对应时间戳画面；
3. `我的`：家属账号、紧急联系人、设备和能力接入状态。

预警详情固定顺序：

1. 具体诈骗场景、介入状态和事件主画面；
2. 预测原因、S0-S5 阶段和介入建议；
3. 时间、位置等基本信息；
4. 可切换的关联画面及每张画面的采集时间戳；
5. 立即介入、现场直播复核、解除风险或标记误报。

画面契约统一使用 `evidence_frames[{captured_at,image_url}]`。App 不从文件名猜测时间，也不把当前直播截图伪装成事件当时画面。历史回放和设备语音提醒入口可以先实现，但后端能力未接入时必须显示“待接入”并返回 `501`。

## 5. 其他模块接入边界

跌倒和心理关怀当前只显示“待模块接入”：

- 跌倒模块未来应预测失衡、步态异常或高危环境趋势，而不只是上报已经倒地；
- 心理关怀模块应输出非诊断性的长期趋势和人工复核建议，不得直接给出医疗诊断；
- 两个模块统一写入 `risk_events`，复用状态流转、幂等、人工介入和审计；
- 新增公共字段时先修改 API 契约和数据库迁移，不允许 App 解析模块私有原始 JSON。

## 6. 演示验收

防诈演示必须覆盖完整的“预测—介入”过程：

1. 萤石与 SenseVoice 提供视觉、通话和语音证据；
2. 状态机在资金损失发生前进入 S2-S4；
3. 家属首页展示当前风险趋势，不把场景拆成两个产品入口；
4. 家属进入预警详情，看到具体场景、阶段和证据；
5. 家属开始介入，事件状态变为 `acknowledged`；
6. 家属实时复核后结束风险或标记误报；
7. 重新查询后状态一致，并能追溯处置动作。

没有真实风险事件时，页面必须显示“持续监测中”，禁止固定演示文案冒充预测结果。
